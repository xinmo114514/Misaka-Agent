# 多窗输入框精修验收记录

## 实现范围

- 仅研究多窗启用内部 `presentation="multi"`；保留同一 Composer、form 和 textarea，不改发送、排队、停止、根主控绑定及草稿／附件逻辑。
- dock 保持页面内真实占位，去掉实色底板和顶线；编辑卡居中、最大 1120px、外侧至少 12px，16px 圆角，默认空卡实测约 87px。
- 输入区与工具行间距 6px，无内部横线；附件／模式／新研究连续靠左，模型与发送／停止靠右。轻量控件约 32px、12px 字号，无常驻实色边框。
- 使用实际卡宽断点：`width < 600px` 模型名称最多 100px，`width < 420px` 图标入口，`width < 360px` 上下文／操作两行。运行、提交与停止反馈较密时，600px 以下按组分两行，避免控件互相覆盖。
- 多窗 textarea 上限仍为 88px；恢复草稿、改变卡宽及往返视图时重测高度，保留节点、选择区和焦点逻辑。
- 沿用原玻璃层、透明回退、语义色和减少动态效果；未新增依赖、设置或后端／IPC 协议。

## 测试先行与复核

基线：87 项定向单测及类型检查通过；保存 16 张多窗矩阵、6 张普通聊天／专注／欢迎页基线截图。先观察限宽、横线、模型宽度和 textarea 缩窄后高度不变的浏览器失败，以及呈现标记／高度重测的单测失败，再实施。

独立复核另发现运行／提交／停止状态的窄宽控件相互覆盖，以及侧栏拖宽产生小数宽度时的断点缺口。分别以实际按钮矩形及 599.5／419.5／359.5px 用例复现后修正，保留所有控制与反馈。
